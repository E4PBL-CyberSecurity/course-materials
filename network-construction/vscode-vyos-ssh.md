# SSH公開鍵認証の補足とトラブル対処

通常の作業は[第8章：SSHでルーターへサインインする](../handbook/08-ssh.md)の順に進める。本書は入力場所、鍵の役割、接続できない場合の確認を補う。VS Codeの導入とターミナルの使い方は[第10章](../handbook/10-vscode.md)を参照する。

## 1. 操作する場所と鍵の役割

表C-1 入力場所とプロンプトの目印

| 入力場所 | 画面の目印と行うこと |
| --- | --- |
| WindowsのPowerShell | `PS C:\…>`。`ssh-keygen.exe`で鍵を作り、`scp`で公開鍵を送る。`ssh`で接続する |
| SSH接続先のVyOS・運用モード | `vyos@PBL-R1:~$`など。`generate public-key-command`で登録用コマンドを生成する |
| VyOS・設定モード | `[edit]`と`vyos@PBL-R1#`など。生成された設定を`commit`で反映し、`save`で保存する |

SSH接続後は、同じターミナルの入力先がVyOSに変わる。運用モードの`exit`でWindowsへ戻る。ホスト名やWindowsユーザー名は機器ごとに異なる。

表C-2 公開鍵認証に関係するファイルと入力する秘密情報

| 項目 | 役割・保存場所 |
| --- | --- |
| 秘密鍵 `id_ed25519` | Windowsの自分のユーザープロファイル内に保管する。他人へ渡さない |
| 公開鍵 `id_ed25519.pub` | 秘密鍵と対になる情報。VyOSへ送って登録する |
| 秘密鍵のパスフレーズ | Windowsの秘密鍵を保護する。鍵作成時に決めたもの |
| VyOSのパスワード | ルーターの`vyos`ユーザーとしてログインするためのもの |
| `known_hosts` | 過去に確認した接続先サーバーのホスト公開鍵を、Windows側に記録するファイル |

`id_ed25519`は既定のファイル名の例。自分の画面に別のファイル名が出た場合は、公開鍵・秘密鍵のファイル名を読み替える。

## 2. 公開鍵ファイルの送付先と取り込みを確認する

### Windowsで公開鍵を送る

Windowsは、ユーザーごとのファイルや設定を「ユーザープロファイル」として管理する。その保存先は、例えば`C:\Users\student`というフォルダーである。

環境変数は、OSやアプリが使う情報を「名前」と「値」の組で持つ仕組み。`USERPROFILE`という環境変数には、今サインインしているユーザーのプロファイルフォルダーの場所が入っている。

PowerShellの`$env:`は環境変数の値を読み取る書き方。`$env:USERPROFILE`が`C:\Users\student`なら、`"$env:USERPROFILE\.ssh\id_ed25519.pub"`は`C:\Users\student\.ssh\id_ed25519.pub`を指す。

班1の送付先は`vyos@192.168.21.1:`。`scp`はSSHでファイルをコピーするコマンドで、末尾の`:`の後ろを省略すると、相手ユーザーのホームフォルダーへ送る。班2〜4は自班の内側IPへ読み替える。

```powershell
scp "$env:USERPROFILE\.ssh\id_ed25519.pub" vyos@192.168.21.1:
```

コピーするのは末尾`.pub`の公開鍵である。VyOSのパスワードを求められたら入力し、完了してPowerShellの入力待ちへ戻るまで待つ。

### VyOSで登録用コマンドを生成する

`ssh vyos@192.168.21.1`で接続し、運用モードで実行する。

```text
generate public-key-command user vyos path id_ed25519.pub
```

`user vyos`は登録先のユーザー、`path id_ed25519.pub`は送った公開鍵ファイルを指定する。表示された`configure`と2行の`set`、合計3行だけをコピーし、同じターミナルへ貼り付ける。先頭の説明行や、最後の入力待ちのプロンプトは含めない。

取り込んだ設定を反映・保存し、運用モードへ戻る。

```text
commit
save
exit
```

`commit`でエラーが出た場合は、`save`や次の手順へ進まず、表示を教員へ示す。反映・保存が終わったら、運用モードでもう一度`exit`でWindowsへ戻り、`ssh vyos@192.168.21.1`で接続し直す。

### 接続時に尋ねられているものを見分ける

表C-3 SSH接続時の表示と入力するもの

| 表示 | 意味と行うこと |
| --- | --- |
| `Enter passphrase for key ...:` | Windowsの秘密鍵を使うためのパスフレーズ。鍵作成時に決めたものを入力する |
| `vyos@192.168.21.1's password:` | VyOSユーザーのパスワード。公開鍵認証が成功していないので、送付・取り込み・保存を確認する |
| `vyos@PBL-R1:~$`など | VyOSへ接続できた。上のVyOSパスワードを入力せず、この表示になれば公開鍵認証は成功 |

## 3. 接続できないときの確認

表C-4 SSH接続・公開鍵取り込みのトラブルと対処

| 症状 | 確認・対処 |
| --- | --- |
| Windowsで`ssh`・`scp`が見つからない | 教員にWindowsのOpenSSHクライアントを確認してもらう |
| 接続がタイムアウトする | [第7章](../handbook/07-cabling.md)で自班ルーターへの通信とTCP/22の結果を確認する |
| `Connection refused` | 接続先IPと、[第6章](../handbook/06-router1.md)のSSHサービス有効化を確認する |
| `scp`でファイルが見つからない | `ssh-keygen.exe`が表示した保存先・公開鍵のファイル名と照合する |
| 生成時にファイルが見つからない | `scp`が正常に終了したか、生成コマンドのファイル名が送った公開鍵と同じかを確認する |
| 生成したコマンドでエラーになる | 公開鍵の行全体を手で編集せず、表示された3行をコピーし直す。教員へエラーを示す |
| 接続時にVyOSのパスワードを求められる | 公開鍵の送付、生成した3行の実行、`commit`・`save`を確認する |
| 秘密鍵のパスフレーズを忘れた | 元のパスフレーズは取り出せない。教員と新しい鍵の作成・登録を行う |
| `REMOTE HOST IDENTIFICATION HAS CHANGED!` | 接続先の機器やホスト鍵が変わった可能性がある。本体の指紋と機器交換の履歴を教員と確認する |

ホスト鍵の変更が正しいと確認できた場合だけ、Windowsで該当IPの古い記録を消す。

```powershell
ssh-keygen.exe -R 192.168.21.1
```

接続し直し、新しい指紋を本体の`show ssh fingerprints`と照合する。自分のログイン用公開鍵の登録と、接続先のホスト鍵の記録は別のものである。

## 4. 完了と返却時の扱い

PC1・PC2で、公開鍵を取り込み・保存したことと、接続し直したときの表示を記録する。秘密鍵・パスフレーズ・VyOSのパスワードは提出物へ入れない。

共用PCの返却時は教員の指示に従う。この実験で新しく作った鍵が不要になった場合だけ、教員がVyOSの該当する登録とWindows側の鍵ファイルを確認して削除する。既存の鍵を再利用した場合は、Windows側の鍵ファイルと、ほかの用途の登録を残す。

参照：[VyOS公式：SSHの操作コマンド](https://docs.vyos.io/en/1.5/configuration/service/ssh.html#operation)、[Microsoft公式：WindowsのSSH鍵管理](https://learn.microsoft.com/en-us/windows-server/administration/openssh/openssh_keymanagement)。
