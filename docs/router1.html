6. ルーターの設定1：NIC・IP・SSH

嶋 直樹　E4 PBL v2.1 / 2026-10-25

印刷・配布用PDF

第5章でインストールしたVyOSをThinkPad本体の画面で操作する。ここでは、本体とUSBアダプターのLANポートがeth0・eth1のどちらに対応するかを確認し、IP設定とSSHの有効化を行う。デフォルト経路とDNSは第9章で設定する。

本体・USBアダプターのLANポートとeth0・eth1を対応させる

Section titled “本体・USBアダプターのLANポートとeth0・eth1を対応させる”
  1. 有線NICのeth0・eth1が両方存在することを確認する。片方しかなければUSBアダプターを接続し直し、型番・ドライバーの対応を教員と確認する。
  2. LANケーブルをいったん外す。本体NICだけを、電源が入ったスイッチへ接続してshow interfacesを再実行する。
  3. 状態表示のState/Link（版によってS/L）を確認する。u/uは管理状態・リンクともUP、u/DはリンクがDOWN。表示の凡例を見て、ケーブル接続でリンクがUPになったNICを記録する。
  4. 本体NICを外してUSB NICへ同じケーブルを挿し、もう一方のリンクがUPになることを確認する。MACアドレスと接続口へ札を付ける。
  5. 対応が分かったら、本体NICを共通スイッチへ接続し直す。内側NICと班専用スイッチは第7章で接続する。

本書の例は本体NIC＝eth0＝外側、USB NIC＝eth1＝内側。逆の場合は以降のeth0・eth1を実物に合わせて入れ替える。

IPアドレスを設定して保存する

Section titled “IPアドレスを設定して保存する”

以下は班1。班2～4は第2章の表のIP・班番号へ読み替える。授業で引き継いだ機器に既存IPがある場合は、追加する前に教員と旧設定を確認する。

setを入力しただけでは、動作中のIP設定は変わらない。変更を準備し、commitで実際の動作へ反映し、saveで次の起動にも使えるよう保存する。

表6-1 設定コマンドで行う操作
入力行うこと
configure設定を変更するモードに入る
set ...指定した値への変更を準備する。まだ実際の動作には反映しない
commit準備した変更を検証し、問題がなければ動作中の設定に反映する。IPやSSHなどがこの時点で変わる
save反映済みの設定をインストール先USBへ保存する。これを省くと再起動で元の設定へ戻る
exit設定モードを終え、状態確認などを行う運用モードへ戻る

commitでエラーが出たら、saveや次の手順へ進まず教員と確認する。成功時は、エラーを出さず[edit]と入力待ちの画面へ戻る場合もある。commitの成功は設定を反映できたという意味で、通信できるかどうかは後の表示とpingで確認する。

show interfacesの出力を読む

Section titled “show interfacesの出力を読む”

次は班1でIP設定後、本体NICだけを共通スイッチへ接続した状態の出力例（入力しない）。MACアドレスは例、loのIPv6など一部の行は省略している。

表6-2 show interfacesで見る欄と判断方法
欄意味と確認すること
InterfaceNICの名前。eth0・eth1が両方ある。loはルーター自身の内部通信用で、LANケーブルの接続口ではない
IP Address設定したIPとネットワークの範囲。班1なら外側は192.168.1.21/24、内側は192.168.21.1/24。設定前の-はIP未設定を示す
S/L左がNICの管理状態、右が物理リンク。u/uは有効でリンクあり、u/Dは有効だがリンクなし、A/Dは設定で無効になっている状態
MACNICを識別するアドレス。接続口の記録と照合する。値はNICごとに異なる
VRF経路を分ける仕組みの所属先。この授業ではdefaultのまま使う
MTU1回に送るIPパケットの最大長（バイト）。有線NICでは例のように1500。ここでは変更しない
Description自分で付けた説明。外側がCOMMON、内側がPBL-LAN1。班番号は自班の値になる

この段階では、外側eth0がu/uで、自班のIP2個が正しければよい。 内側eth1はまだケーブルを挿していないので、例のu/Dでよい。第7章で両側の配線を終えたら、2口ともu/uになることを確認する。u/uだけでは相手とのIP通信の成功までは分からない。

IPが違う、設定後も-のまま、外側がu/Dなら先へ進まず、入力したIP、commitの結果、ケーブルとスイッチの電源を確認する。A/Dならケーブルだけでは直らないため、教員とNICの設定を確認する。

already existsやNo configuration changes to commitは同じ値が設定済み・反映する変更がないという意味で、構文エラーや設定検証の失敗とは分けて読む。

本体NICを共通スイッチに接続できたら、運用モードで次を実行する。

pingの出力を読む【VyOS】

Section titled “pingの出力を読む【VyOS】”

pingは、指定した相手に応答を求める小さな通信を送り、返事が届くかを調べる。count 4は4回送って終了する指定。次は成功時の出力例（入力しない。時間は例）。

表6-3 VyOSのping出力の読み方
表示意味
PINGの行調べている宛先。ここでは共通GWの192.168.1.1。名前で指定した場合は、名前に続く括弧内にIPが出る
56(84) bytes、64 bytes通信の長さ。送信データ56バイト、IPv4・ICMPのヘッダー込みで84バイト。返信の64はICMPの長さ。成功の判定には下の応答元・受信数・損失を見る
from 192.168.1.1応答した相手。調べたい宛先からの返事であることを確認する
icmp_seq=1～4送った通信の番号。例では4回とも返事が来ている
ttl=64受信した返信があと何台のルーターを通過できるかを示す値。実際に通った台数や通信時間ではない。64を固定の正解にしない
time=0.264 ms1回の通信の往復時間。msはミリ秒で、1msは1000分の1秒。時間の値は毎回変わる
4 packets transmitted、4 received、0% packet loss4回送信、4回受信、損失0%。この例では宛先から4回とも応答があり、疎通成功と判断する
time 3107ms、rttの行前者は試験全体にかかった時間。rttは往復時間の最小・平均・最大・ばらつき（min・avg・max・mdev）をミリ秒で示す

失敗時の集計の出力例（入力しない、抜粋）：

これは4回送って返事が0回、すべて失敗したという意味。Destination Host Unreachable（宛先へ到達できない）や100% packet lossが出たら成功ではない。エラー行のFrom ...はエラーを知らせた機器で、宛先からの正常な返事とは異なる。一部だけ欠けた場合も損失を記録し、配線や設定を確認して再試行する。応答がない原因は相手の停止だけとは限らず、配線・IP・経路・通信の制限なども考えられる。

共通GWは外側と同じLANなので、デフォルト経路をまだ設定していなくても到達できる。応答がなければ本体NICと共通スイッチの配線、IP重複、共通GWの稼働を確認する。内側からの確認は第7章で行う。

SSHサービスを有効にする

Section titled “SSHサービスを有効にする”

SSHは標準のTCP/22で接続を受け付ける。第8章では自班ルーターの内側IPへ接続する。最後のコマンドで本体が表示した鍵の種類とSHA256指紋を記録し、第8章でWindowsに表示された値と照合する。

完了の確認

Section titled “完了の確認”

次の内容を記録する。

  • ThinkPad本体のLANポートとUSBネットワークアダプターのLANポートが、それぞれeth0・eth1のどちらに対応するか
  • 外側・内側NICに設定したIPアドレス
  • saveで設定を保存できたこと
  • SSHサーバーの指紋

パスワードや認証設定を含む完全な設定出力は提出物へ貼らない。
