7. 配線を変更しWindowsに固定IPを設定する

嶋 直樹　E4 PBL v2.1 / 2026-10-25

印刷・配布用PDF

第6章で確認した外側・内側NICを使って、第2章のネットワークを完成させる。設定対象は班用のWindows PC2台であり、ルーター用ThinkPadではない。

ルーターとスイッチをつなぐ

Section titled “ルーターとスイッチをつなぐ”
  1. ThinkPad本体の外側NICを共通スイッチにつなぐ。
  2. USBアダプターの内側NICを班専用スイッチにつなぐ。
  3. Windows PC1・PC2を班専用スイッチにつなぐ。班専用スイッチと共通スイッチは直接つながない。
  4. ThinkPadでshow interfacesを実行し、eth0・eth1の自班IPが正しく、S/Lが両方ともu/uであることを確認する。表示例と各欄の意味は第6章を参照する。

Windowsの有線NICを手動設定する

Section titled “Windowsの有線NICを手動設定する”
  1. 画面下の「スタート」をクリックし、「設定」を開く。見つからなければ「すべてのアプリ」から「設定」を選ぶ。
  2. 「ネットワークとインターネット」→「イーサネット」を選び、班専用スイッチへ接続した有線アダプターの画面を開く。複数ある場合はアダプター名と接続状態を確認する。Wi-FiやWSL用の仮想アダプターは設定対象にしない。
  3. 現在のIP・DNSの割り当て方法と値を記録する。元に戻すため、変更前の画面を撮影して残す。
  4. 「IP割り当て」の「編集」をクリックする。「手動」を選び、「IPv4」をオンにする。表7-1「班1のWindows PCのIPv4設定」の自分のPCの列から、IPアドレス、サブネットマスク、ゲートウェイを入力し、「保存」をクリックする。「ユーザー アカウント制御」が表示されたら「はい」を選ぶ。
  5. イーサネットの画面で「DNSサーバーの割り当て」の「編集」をクリックする。「手動」を選んで「IPv4」をオンにし、優先DNSに自班ルーターの内側IPを入力する。代替DNSは空欄にし、「DNS over HTTPS」が表示される場合は「オフ」を選んで保存する。この授業の班DNSは通常のDNS通信を使う。版によってDNSの入力欄が「IP設定の編集」内にある場合は、そこで同じ値を設定する。
  6. イーサネットの画面に戻り、表示されたIP・マスク・ゲートウェイ・DNSを表7-1「班1のWindows PCのIPv4設定」と照合する。
表7-1 班1のWindows PCのIPv4設定
班1の項目PC1（A）PC2（B）
IPアドレス192.168.21.10192.168.21.11
サブネットマスク255.255.255.0255.255.255.0
デフォルトゲートウェイ192.168.21.1192.168.21.1
優先DNS192.168.21.1192.168.21.1
代替DNS空欄空欄

「サブネット プレフィックスの長さ」という入力欄が表示される版では、サブネットマスク255.255.255.0に対応する24を入力する。IPアドレス欄に/24を付け足さない。

Wi-Fi・VPNなど別経路は教員の指示で切断する。実験用NIC以外の固定IPを変更しない。DNSサービスは第9章で設定するため、この時点の名前解決失敗は想定内である。

Windowsに設定されたIP・DNSを確認する

Section titled “Windowsに設定されたIP・DNSを確認する”

ipconfigは、このWindows PCのネットワーク設定を表示するコマンドである。実験用の有線アダプターのIP・サブネットマスク・ゲートウェイ・DNSを、表7-1「班1のWindows PCのIPv4設定」の自分のPCの列と照合する。/allを付けるのは、通常のipconfigでは出ないDNSサーバーやDHCPの有効状態も表示するため。

第4章の起動手順と同じ方法で、Windows PCのターミナルを開き、PowerShellを使う。

実験用の有線アダプターの欄を見つける

Section titled “実験用の有線アダプターの欄を見つける”

出力は、アダプターごとに分かれている。「イーサネット アダプター イーサネット」などの見出しを探す。名前はPCにより「イーサネット 2」などになる。Wi-FiやvEthernetなどの仮想アダプターの欄と取り違えない。

同じ欄にある「物理アドレス」は、そのLANアダプターを識別する番号（MACアドレス）。「設定」→「ネットワークとインターネット」→「イーサネット」で見たアダプター名と「物理アドレス（MAC）」を照合し、班専用スイッチにつないだアダプターの欄であることを確認する。

値が違う、ゲートウェイ・DNSが空欄、DHCPが「はい」の場合は、同じ有線アダプターの「設定」画面へ戻り、入力値と保存を見直す。対象の欄に「メディアは接続されていません」またはMedia disconnectedと出る場合は、ケーブル、班専用スイッチの電源、アダプターの接続を確認する。

IP・マスク・ゲートウェイ・DNSが自班の値と一致し、DHCPが無効であることを記録してから、次の通信確認へ進む。 この表示が正しくても、相手まで通信できることはまだ確認できていない。

-n 4は4回送って終了する指定。次は班1のPCから自班ルーターの内側IPを調べたときの出力例（入力しない）。日本語Windowsの例で、時間や文言は環境により異なる。

表7-3 Windowsのping出力の読み方
表示意味と確認すること
192.168.21.1からの応答自班ルーターから返事が来た。バイト数・時間・TTLが続く応答行を確認する
バイト数 =32返ってきたデータの長さが32バイト。VyOSの例の64はICMPヘッダーも含む表示なので、数値をそろえない
時間 <1ms往復時間が1ミリ秒未満。時間は毎回変わる。TTLは返信があと何台のルーターを通過できるかを示す値で、64を固定の正解にしない
送信4・受信4・損失04回送った通信に対して4回受信し、失われた数が0。上の宛先からの正常な応答行と併せて成功を判断する
最小・最大・平均往復時間の集計。1ms未満が0msと表示される場合もあり、時間が全くかかっていないという意味ではない

宛先からの正常な応答が4行あり、損失0であることを確認する。 要求がタイムアウトしました。は時間内に返事がなかったという意味。宛先ホストに到達できません。も成功ではない。このエラー通知が受信数に数えられる場合があるので、受信4・損失0だけで成功と判断しない。

Windows PC同士へのpingはWindowsの受信規則により応答しないことがある。ルーターへの疎通と分けて判断し、確認のためにファイアウォール全体を無効にしない。

SSH用のポート22へ接続できるかを確認する

Section titled “SSH用のポート22へ接続できるかを確認する”

Test-NetConnectionは、指定した相手への接続を調べるコマンドである。ここでは、自分のWindows PCから班ルーターのSSH用の窓口（TCPポート22）へ接続できるかを調べる。pingで返事が来ても、SSHの窓口が使えるかは別に確認する。

192.168.21.1は班1のルーターの内側IP、-Port 22はTCPポート22を調べる指定。班2～4はIPを自班のルーターへ読み替える。PC1・PC2からそれぞれ実行し、結果が表示されて入力待ちに戻るまで待つ。

失敗した表示を読む

Section titled “失敗した表示を読む”

相手はpingに応答するが、TCPポート22には接続できない場合の出力例（入力しない、関連する行の抜粋）：

PingSucceeded : Trueはpingへの応答があったという意味である。上の例のSSH用ポートの接続試験は、TcpTestSucceeded : Falseなので失敗。TCP connect to ... failedという警告が出ることもある。これはTCP接続の失敗を知らせている。PingReplyDetails (RTT)が出る場合はpingの往復時間で、ポート22の成功判定には使わない。

  1. RemoteAddressとRemotePortを見て、宛先IPと22番を正しく入力したか確認する。
  2. InterfaceAliasとSourceAddressを見て、実験用の有線アダプターと自班のPCのIPを使っているか確認する。違っていたら、この章のIP設定と配線を見直す。
  3. pingにも応答しない場合は、PCのIP、配線、スイッチの電源、ルーターの内側IPを確認する。
  4. pingは成功してTCPだけ失敗する場合は、第6章のSSHサービス設定を見直す。ルーターが内側IPのポート22で受け付ける設定を反映・保存できたか、教員と確認する。通信制限がある場合も教員へ確認し、ファイアウォール全体を無効にしない。

失敗したまま第8章のログインへ進まず、原因を直して同じコマンドを再実行する。

完了の確認

Section titled “完了の確認”

2台とも自班ルーターの内側IPへpingが成功し、TCPポート22への接続試験がTrueであることを記録する。実験終了後に共通LAN直結へ戻す場合は、ケーブル移動前に教員の指示に従い、同じ「設定」→「ネットワークとインターネット」→「イーサネット」の画面を開く。「IP割り当て」と「DNSサーバーの割り当て」を、それぞれ元の「自動（DHCP）」へ戻して保存する。
